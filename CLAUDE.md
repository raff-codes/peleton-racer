# CLAUDE.md

Personal Expo app: a 3D race game for the Peloton bike tablet. See `README.md` for the data path, commands
and layout. General Expo guidance is in `AGENTS.md`, but note the deviations below.

## Invariants

- **Read-only bike access.** The sensor module only reads power/cadence/resistance. Never add writes to the
  Peloton services.
- **Android only**, sideloaded onto the tablet. No iOS/web targets; `android/` is generated by prebuild.
- No Expo Router yet: `App.tsx` switches screens from state: no active profile → `ProfilePicker`; a ride in
  progress → game; otherwise `useSettings().view` (menu / history). Revisit if navigation grows deeper.
- Ride data is local-only SQLite (`src/data/db.ts`). Schema changes: append a new entry to `MIGRATIONS`, never edit
  an existing one (it's applied by `PRAGMA user_version`). Saved traces are replayed as ghosts, so keep the
  `RideTrace` format backward compatible.
- Maps (`src/game/maps.ts`) pair a `buildLoop` circuit with a `Theme`. Circuits must stay ~210–450 m from the origin
  (lake inside, foothills outside).
- The render loop (`useFrame`) must not trigger React renders per frame. Game state is mutable in `race.ts`;
  the HUD gets throttled snapshots via `useHud.publish`.
- Physics and race logic stay pure TS (no React/three imports) so they can be simulated headless with `tsx`.

## Conventions

- pnpm; Biome (single quotes, semicolons, no trailing commas, 120 cols); strict TS with
  `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.
- Run `pnpm typecheck` and `pnpm lint` before calling work done.
